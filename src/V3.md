# FOGBOUND Warlord v0.3: rework contract (binding for all lanes)

Rework of the Warlord mode (agreed 2026-10-10). The player loop becomes: capture zones -> they grow and defend themselves -> monsters raid them ->
research and teleport around a big map -> take rival districts until their Dark Tower is exposed -> destroy it. Defences (walls/towers) stay
important and effective. Gold matters. Read CLAUDE.md "Design v0.3" for the full design; this file is the technical contract.

## Rules of engagement (parallel agents share one working tree)
- Edit existing shared files (sim.js, data.js, ai.js, render.js, ui.js, controls.js, world.js, nav.js, main.js, index.html, style.css) ONLY with small
  targeted Edit calls (never rewrite/Write a whole existing file; other agents are editing it at the same time). Re-read the region right before editing.
- Put your logic in YOUR OWN files (listed per lane). Shared files get thin call-outs only.
- Sim stays deterministic and has no DOM/Three imports (must run in Node). Use `st.rng()` for randomness, never Math.random in sim code.
- Use `WORLD.half` / `WORLD.size`, never literal 200/400 (the MAP lane makes the island bigger, target 800 m).
- Do not break the build: `node --check` every file you touch; `node tools/simtest.js 6` must keep running without exceptions.
  Never leave a shared file in a syntactically broken state, not even briefly (others import it).
- Do not start long-running servers on a fixed port. If you need the browser, use a free port >= 8200 + your lane number, and kill it afterwards.
- Add tests as `tools/v3-<lane>-test.js` (plain node scripts that exit non-zero on failure). Document your final API at the bottom of this file (append a section; do not edit others').
- When finished, report: files changed, state fields/commands/events added, what is verified, what is left. Keep the report under 300 words.

## Extension points (already wired)
Sim (`src/v3hooks.js` calls these on the lane modules `regions raids research perks dungeons pois travel`):
`init(st)`, `update(st, dt)`, `command(st, team, c) -> bool` (any `c.t` not handled by sim.js `runCommands` reaches it), `onDamage(st, src, t, amt, o) -> amt` (return <= 0 cancels), `onKill(st, t, src)`.
Internals via `import { simApi } from './sim.js'` (use at call time, circular import): addEnt, newAgent, recalc, spawnUnit, spawnMonster, spawnCamp, hireUnit, makeHero, addXP, giveXP, kill, eliminate, dropItem, rollItem, equipItem, addBuilding, recomputeInfluence, moveBy, stepToward, goTo, findTarget, atkDamage, doAttack, tickCd, xpNeed, unitXpNeed, ev, rf, srcOf. Lanes may add more to `simApi` (append to the object at the bottom of sim.js).
Client (`src/v3view.js`): scene modules `regions_view raids_view dungeons_view` export `createView(ctx)` -> `{frame(st, alpha, dt), handleEvents(events), dispose?}`;
DOM modules `travel_ui research_ui perks_ui` export `createUi(ctx)` -> `{update(dt), handleEvents(events), open?}` (`open` true while a panel/map is up so controls ignore game keys; controls lane wiring: `game.ui.v3.open`).
Scene ctx: `{THREE, scene, camera, st, world, localTeam, wv, makeBar, setBar, ringMat, ringFx, spawn, burst, addFx, focus, visibleNow, vis}`. UI ctx: `{game, st, local, ui, renderer}`.
New input commands are objects pushed to `input.cmds` (same path humans and AI use): `{t:'...', ...}`.

## Shared state (st is the single source of truth; all JSON-able, ids are numbers)
Note `st.zones` ALREADY EXISTS (fire/gas ground effects). Territory is `st.regions`.
- `world.sites = {regions, lairs, dungeons, pois, waystones}` from `src/sites.js generateSites(world)` (placeholder now, MAP lane makes it real). Static layout only:
  - region `{id, name, x, z, r, kind:'keep'|'district'|'free', home:teamId|-1, nodeIdx:index into world.features.nodes|-1, tier?, wsId}`
  - lair `{id, x, z, tier, quadrant}`; dungeon `{id, x, z, tier, theme, quadrant}`; poi `{id, type, x, z, quadrant}`; waystone `{id, x, z, regionId}`
- `st.regions[]` (REGIONS lane): `{id, ...site fields, owner:-1..3, stage:0..3 (0 outpost,1 hamlet,2 village,3 fortress district), prog:0..1 (capture), capTeam, heldT, guards:[entityIds], ruined:bool, income:gold/s}` plus `st.regionAt(x,z)` helper exported from regions.js.
  `towerShielded(st, teamId)` (regions.js): true while the lord still owns >= 1 of its 3 home districts. Dark Tower takes no damage while shielded (enforced in regions.onDamage).
- `st.lairs[]`, `st.raids[]` (RAIDS lane): lair `{id, x, z, tier, power, nextRaidT, alive}`; raid `{id, lairId, targetRegion, t0, arriveT, ids:[monsterIds], state:'warning'|'marching'|'done'}`. Events: `{type:'raidWarn', region, eta, tier}`, `{type:'raidHit', region}`.
- `team.res` (RESEARCH lane): `{pts, done:{id:true}, active:{id, left}|null, queue:[]}`; team field `team.slots` (servant cap from tower tier). Cmd `{t:'research', id}`; `{t:'hire', idx}` keeps working (roster index within the faction's servant list).
- `team.perks` (PERKS lane): `{offers:[[perkIds...]], picks:[ids], ver}` ; cmd `{t:'pickperk', idx}` (picks from `offers[0]`). `team.sk` (skills) is kept.
- `st.dungeons[]`, `st.pois[]` (WORLD CONTENT lane): dungeon `{id, ...site, state:'locked'|'open'|'cleared', by:-1..3, bonusKind}`; poi `{id, ...site, used:bool, cd:0}`.
- `st.waystones[]` (TRAVEL, in travel.js): `{id, x, z, regionId, disc:[bool x4]}` (disc[team] = discovered; own keep waystone always discovered). Cmd `{t:'tele', ws:id}` starts a channelled teleport (cancelled by damage or moving), cooldown scaled by distance; `team.tele = {ws, left}`; going to the own Dark Tower is cooldown-free.
- Gear slots: `weapon, helmet, armor, amulet` (replaces weapon/armor/charm). `e.eq[slot]`, `ITEM_SLOTS` in data.js.
- Win: a team is eliminated when its Dark Tower (building type 'heart', renamed in UI/text only; keep the id `heart` internally) dies. Last team alive wins. The Sunken Temple ritual is REMOVED (temple node, beam, RITUAL_TIME, ritual UI).
- Servants: unit `e.kind==='unit'`, `e.lvl 1..6`, `e.xp`; overhead plate shows `(lvl) [health bar]`.

## RAIDS lane API (raids.js / raids_view.js, appended by the RAIDS lane)
- State: `st.lairs[]` `{id,x,z,tier,power,nextRaidT,alive,entId,camp,alone,raids,weak,biome,destroyedT,rebuildT,destroyedBy}`; `st.raids[]` `{id,lairId,targetRegion,team(owner),t0,warnT,arriveT,state:'warning'|'marching'|'done',ids,tier,size,big,razeT,arrived,x,z(band centroid),dx,dz(region),result}`; `st.raidCtl`.
- A lair is a stationary neutral monster entity (`e.lair=id`, model `lair` = empty shell, raids_view draws the spire) plus a guard camp (`st.camps[lair.camp].lair`). Raid monsters have `e.raid=id`, `e.camp=-(100+id)` (no st.camps entry; sim.js kill() tolerates a missing camp) and are driven by `raidMon()` from sim.js monUpdate.
- Exports (raids.js): `activeRaids(st) -> [{id,region,x,z,eta,tier,state,team,big,size,lair,tx,tz}]`, `lairList(st)`, `lairPower(st,lair)`, `regionDefense(st,region)`, `launchRaid(st,lair,region,{big})`.
- Events: `raidWarn {region,eta,tier,raid,team,x,z,name,big,lair}` (+ msg to the target team), `raidMarch`, `raidHit {region,x,z,razing,team,raid}`, `raidEnd {raid,region,result:'razed'|'repelled'|'expired'|'moot',x,z,team}`, `raidVanish {x,z}`, `lairDown {lair,x,z,team}`, `lairRebuilt`.
- Uses from REGIONS: `regionById`, `razeRegion(st,id)`. Dread Moon: launched from `update` when `st.dreadWarned` (big multi-lair raid on the leader). Tuning: `RAIDS` in data.js.

## REGIONS lane API (regions.js, regions_view.js)
- Config: `REGION` block in data.js (stage times, capture speed, income per stage, mine/obelisk node gold, guard counts/levels, invest costs). `HEART_GOLD` is now 0.1 and `ECON.perCell` 0: gold comes from regions.
- State: `st.regions[]` = site fields + `{owner, stage 0..3, prog 0..1 (capture of capTeam), capTeam, heldT, guards:[entIds], ruined, ruinedT, income}`. Non-enumerable helpers: `st.regionAt(x,z)`, `st.regionMap` (id -> region). Keeps are always owned by their lord (stage 3, no guards, not capturable). Home districts start owned at stage `REGION.homeStage`.
- Nodes (mines/obelisks) with a region get `node.reg = regionId`; `nodesUpdate` skips them and `regions.update` drives `node.team/prog` from region ownership. Node gold is paid via `region.income` (only while owned).
- Exports: `regionAt(st,x,z)`, `regionById`, `regionsOf(st,team)`, `homeDistricts(st,team)`, `towerShielded(st,team)`, `setOwner(st,region,team,reason)`, `razeRegion(st,regionId)` (RAIDS: burn a region to ruins, owner -1), `patrolStep/patrolLeash` (used by sim.js unitUpdate), `regionIncome(st)` (called from the sim income tick).
- Guards: normal team units with `e.guard=true, e.reg=regionId, mode:'patrol'`; excluded from `servants()`, XP share, gold/xp bounty, item pickup. Fixed level/tierMul per stage; free respawn after `REGION.guardRespawn` s when no enemy stands in the region.
- Command `{t:'develop', region:id}`: pay `REGION.invest[stage]` to jump to the next stage immediately.
- Events: `{type:'regionChange', region, owner, prev, reason:'capture'|'raze'|'elim'|'init', x, z, name, ruined}`, `{type:'regionStage', region, owner, stage}`, `{type:'towerWarded', team, by, x, z}` + a throttled `msg` 'The tower is warded: take the districts first' to the attacker.
- Dark Tower damage: `regions.onDamage` returns 0 for a 'heart' while its lord owns >=1 home district (AI: capture all 3 districts first).
- Test: `node tools/v3-regions-test.js`.

## WORLD CONTENT lane API (dungeons.js, pois.js, wc_util.js, dungeons_view.js, pois_view.js)
- Sunken Temple / ritual / beam REMOVED (no temple node, `st.ritual`, `st.beamOn`, RITUAL_TIME, BEAM_TIME; `NODES.temple` gone). Boss = guardian of each `sunken` dungeon.
- `st.dungeons[]`: site fields + `{r, name, state:'locked'|'open'|'cleared', by, bonusKind, camps:[campIds], bossCamp, bossId, bossPos, disc:[x4], armed, total, left}`. Monsters spawn lazily when a unit comes within r+60 m (`armed`). Dungeon camps have `camp.noResp` (never respawn). Clearing = every monster + boss dead; credit = boss killer (else last team to hurt a dungeon monster).
- `team.bonus = {towerDmg, servDmg, heroDmg, heroHp (% less damage), income (gold/s), slots, regen (% max HP/s within 40 m of the tower)}` (research bonus goes straight to research points). **TOWER lane: add `team.bonus.slots` to the servant cap.** `dungeons.bonusOf(team, kind)`. Tuning: `DUNGEON` in data.js.
- `st.pois[]`: site fields + `{used, cd, disc:[x4]}` + per type (`left` well, `q{team}` witch, `camp` cage/hoard/bridge, `troll`, `owner/vision` watchtower, `state/team/x,z/dx,dz/ambush` caravan). `team.poiNear` = poi id in reach (5 m) or 0. Command `{t:'poi', id}` (E key in controls.js; AI can push the same). Tuning: `POI` in data.js.
- Events: `{type:'discover', kind:'dungeon'|'poi', id, team, x, z, poi?}`, `{type:'dungeonCleared', id, team, x, z, kind}`, `{type:'poiUse', id, kind, team, x, z, ok}`.
- Cross-lane calls (all optional/defensive, see wc_util.js): `perks.grantXP(st, teamId, amt, reason, x, z)` (fallback `simApi.giveXP`), `research.addPoints(st, teamId, n)` (fallback bumps `team.res.pts`), `perks.reroll|rerollOffers|rerollPerks(st, teamId)` (hidden shrine).
- render.js `updateVision` marks claimed watchtower POIs (`p.owner===localTeam && p.vision`).
- Tests: `node tools/v3-world-test.js` (sim), `node tools/v3-world-viewtest.js` (scene code under Node).

## TOWER+SERVANTS+RESEARCH lane API (research.js, servants.js, units_data.js, research_ui.js, models_servants.js, plates.js)
Data (all re-exported from data.js): `UNITS` (35 defs incl. hidden temp summons), `FACTIONS[i].units` = 8 servant types: [0 melee, 1 ranged/melee2, 2 tank] free from the start, [3 healer, 4 summoner, 5 scout, 6 elite, 7 siege] unlocked via `UNITS[k].unlock` = research id (dom1/dom2/dom3/siege1).
`TOWER_TIERS` (Dark Tower tier 0..4: slots 4/6/8/10/12, hp/dmg/range/cd multipliers), `RESEARCH` (id -> {branch, name, desc, cost, time, pts?, req[], eff}), `RESEARCH_BRANCHES`, `EVOLVE_MODS/NAMES`, `ROLE_INFO`, `TOWER_BUILDINGS` (brazier, frostspire; BUILDINGS[x].needs = research gate). `SERVANT_CAP` = 12 is only the absolute max; the live cap is `team.slots`.
State: `team.res {pts, done{id:true}, active{id,left,total}|null, queue[{id,total}]}`, `team.tier`, `team.slots`, `team.mods {unitHp, unitDmg, siegeDmg, siegeHp, siegeCost, xp, resSpeed, rev, teleCd, income}` (multipliers, 1 = none; TRAVEL lane: multiply the teleport cooldown by `team.mods.teleCd` or call `research.teleMul(team)`), `team.up` (legacy forge tiers wall/blade/plate/fletch are now SET BY research; `team.up.hpMul/dmgMul/siegeHp` added), `team.evoN` (servants awaiting an evolution pick).
Servant entity fields: `e.role`, `e.sv {heal, summon, aura}`, `e.vision`, `e.bldMul`, `e.evo` (0/1/2), `e.evoName`, `e.evoReady`, `e.owner` (summoner id on temp summons), `e.temp`. NOTE: region guards (`e.guard`) are `kind:'unit'` of the team: servant counting (`servants.servantCount`) excludes them; `sim.servants()` does not.
Commands: `{t:'research', id}` (pays gold+pts, starts or queues, queue max 2), `{t:'resboost'}` (1 point = -20 s), `{t:'rescancel'}` (60% refund), `{t:'evolve', id, to:0|1}`, `{t:'hire', idx}` (idx into faction roster; fails with a message when locked / no slot / no gold). Legacy `{t:'upgrade', id}` now forwards to research `id+tier`.
Events: `research {team,id,name,branch}`, `researchStart`, `resPoints`, `evolve {id,x,z,team,name,to}`, `heal {x,z,amt,team,from}`.
Exports for other lanes: `research.addPoints(st, teamId, n)` (libraries / ruins / dungeons), `research.has(team, id)`, `research.aiPick(st, team)`, `servants.hireBlock(st, team, idx)` (null or reason), `servants.hireCost`, `servants.servantCount`, `servants.evolve`.
Rules: no servant upkeep. Dark Tower tier raises max HP, arrow damage/range and slots. Forge now = +30% research speed while built (U opens the Dark Tower panel; the old forge panel is dormant). Research-gated buildings: `canPlace` returns 'Research: <name>'.
Client: `research_ui.js` panel (U, Esc closes) + a strip in the Servants box (tier, research bar, quick roster for types 3..8, evolve hint); `plates.js` unit plates `(lvl) [bar]` via render.js; `models_servants.js` builders + `lookOf/applyLook` (visible pauldrons/crest at lvl 3+/5+, glow and spikes after evolution; render.js `swapLook` rebuilds the model when the look key changes).
Tests: `node tools/v3-servants-test.js`, `node tools/v3-defense-test.js [seeds]`.

## Travel + UX lane (travel.js, travel_ui.js, shell)
- State: `st.waystones[] = {id,x,z,regionId,name,disc:[bool x4]}` (own keep always discovered; others by walking within 12 m or by owning the region). `team.tele = {ws,left,total,x0,z0,t0}|null` (hero.tele mirrors elapsed time for render/ui). Old waypoint-stone building, `setwp`, hold-T, `selectedWaypoint`, `team.wpSel` usage are removed; `waypointsOf` (re-exported from sim.js) now returns discovered usable waystones in the legacy shape.
- Commands (human and AI use the same): `{t:'tele', ws:id}` (or `ws:'home'`) starts a 3.5 s channel at the hero's position; `{t:'telecancel'}`. Cancelled by damage, movement (manual move, goto, charge) or stun. Cooldown = min(60, 8 + dist/20) s, none for the own Dark Tower (still channelled). Enemy-owned region (or enemy keep) waystones and undiscovered ones are refused. AI: ai.js `startTele` pushes `{t:'stop'},{t:'tele',ws}` and stands still; it no longer starts a channel within 2.5 s of being hit.
- travel.js exports: `TRAVEL`, `destinationsOf(st,team,includeBlocked)`, `canTeleport`, `cooldownFor`, `homeWaystone`, `isBlocked`, `wsOwner`, `arrivalFor`, `cancelChannel`.
- Events: `telestart`/`tele` (existing; enemies within 70 m see beams), `telecancel {team,why}`, `discover {kind:'waystone',how:'walk'|'region',team,id,name,x,z}`.
- Client: `travel_ui.js` full-screen map (M; Enter/click confirms; Esc closes), key help (F1 or ?; other lanes may append `window.__v3help.push({title, rows:[[key,text]]})`), topbar tower-tier + region-count pills, raid banner (`#v3Raid`) fed by `raids.activeRaids`, minimap overlays via `createUisV3(...).drawMinimap(mx,P,renderer,dt,'under'|'over')` (a lane UI may export `drawMinimap` too). Minimap: click = ping, click on a waystone or Shift+click = open map. `ui.v3.open` is true while the map/help is open; controls.js then drops hotkeys, clicks and movement. Shared CSS: `.v3-panel`, `.v3-btn`, `.v3-x`, `.v3-overlay`, `.v3-hd`, `.v3-row`, `.v3-note`.
- Tests: `node tools/v3-travel-test.js`.

## HERO lane API (perks / skills / gear)
- `team.perks = {offers:[[ids]], picks:[ids], ver, disc:{}}`; cmd `{t:'pickperk', idx}` (alias `pickskill`). offers[0] is a perk card (PERKS ids) or a skill card (SKILLS ids). Every hero level queues a perk card; levels in `SKILL_LEVELS` (2,4,..,12) also queue a skill card. MAX_HERO_LVL 14.

- Gear slots weapon/helmet/armor/amulet (`charm` removed). `rollItem(rng,tier,{danger})`; sim `rollItem(st,tier,{x,z,...})` scales by distance from keeps. Amulets always roll a build-definer affix (cdr, skillDmg, skRad, thorns, killHeal, killGold, killHaste).
- Tests: `node tools/v3-hero-test.js`, `tools/skillcheck.js`, `tools/v3-hero-pace.js`.

## MAP lane API (800 x 800 m island)
- `WORLD = {size 800, half 400, navCell 2, navN 400, infCell 8, infN 100}` (influence cells are 8 m so sim cost stays as on the old map; use `WORLD.infCell`, never a literal 4). Keeps: `world.hearts[k]` at (+-262, +-262) (k = NW, NE, SE, SW), `hearts[k].top` = plateau height. Layout is authored once in `src/mapdata.js` (NW quadrant, rotated 4x; seeds mirror it across the NW diagonal for half of all seeds); `generateWorld(seed)` ~0.6-1.5 s.
- Keeps are plateaus with 2 ramps, inside a ridge ("Rampart", ~120 m radius) with 3 passes (17-33 m wide). `world.chokes` / `sites.chokes`: `{kind:'pass'|'ramp', home, x, z, w, dx, dz}` (plug these with walls). Canyons on the diagonal avenue and the west gorge, lakes with fords on the four axes, crater ring (4 diagonal gaps) in the centre.
- `world.features.{nodes,camps,chests,shrines}` entries gained `q` (quadrant 0-3, -1 shared/centre); `features.boss` is kept at (0, 7). `world.spots`, `world.info`.
- `sites`: regions = 4 keep + 12 districts (3 per lord, "Inner Hollow" etc.) + 40 node regions + 12 extra free regions (Crossroads, Highfold, Ashen Hamlet per quadrant); 12 lairs (3/quadrant); dungeons: 3 per quadrant (crypt, forge, warren) plus ONE central `theme:'sunken'`, `quadrant:-1` at (0,0); 48 pois (all 12 types, 4 each); waystone per region. All reachable, level ground, exactly 4-fold symmetric. Test: `node tools/v3-map-test.js [seeds] [--astar]`; view page `tools/v3-map-view.html`; PNG `node tools/worldmap.js seed out.png px`.
